# screenwriting-skills（编剧技能集）

[English](README.md) · [日本語](README_JA.md) · [한국어](README_KO.md) · [Français](README_FR.md)

把 45 本编剧/剧作理论书籍与 23 卷出版剧本、曲谱（中、美、英、日、韩）提炼成的 24 个 agent skill，面向 [Claude Code Skills](https://docs.anthropic.com/en/docs/claude-code/skills) 与 [OpenAI Codex](https://developers.openai.com/codex/build-skills)，覆盖电影长片、电视剧集、舞台剧。

所有 `SKILL.md` 文件遵循开放的 [agentskills.io](https://agentskills.io) 标准，Claude Code 与 Codex 通用，装一次，两个 Agent 都能用。

**用你自己的语言提问即可。** skill 正文是中文，因为来源多为中文原著或中译本；这只是文本放在哪里的问题，用英语、日语、韩语、法语提问，就用那种语言得到回答。为什么 skill 只有中文一份、不另出译本，见[多语言支持](#多语言支持)。

## 多语言支持

**skill 只有一份，语言到用的时候再解决。** skill 只写一遍、用中文写，agent 用你提问的语言交付。

这是权衡过才定下的，也不是一开始就这么定。曾经有过英文版，一个把 20 个 skill 全部译过去的平行插件 `screenwriting-en`，在 [#3](https://github.com/jtydhr88/screenwriting-skills/issues/3) 里被提出、做完、合并过，现在已经撤掉。否决它的理由，放到其他任何一种语言上都一样成立：如果读不懂中文的读者该有一份译本，那读不懂英文的读者也该有，接下来就是日语、韩语、法语、俄语。五种语言就是 230 个文件各改各的，哪一份已经过时，没人说得清。翻译本身花不了多少工夫，真正的代价在后头：**只要另出过一份译本，就再没有原则性的理由拒绝第二份**。

所以只在源头守住一份中文，其余的事到用的时候再办：

- **输出语言跟着提问走。** 用法语问，用法语答。不需要开关，不需要另外装一份。
- **术语锚在原词上。** 这一行的术语原本就是英文：*logline*、*act out*、*beat sheet*、*showrunner*、*staff writer*；中文书里的"计程绳""出幕""节拍表""剧目管理人""试用编剧"是译文，而且各家译得不一样。[`sw-workflow/terms.md`](plugins/screenwriting/skills/sw-workflow/terms.md) 把每个概念锚回它的原词，agent 照表还原，不自己造词。这一张表同时服务所有语言，因为写日语、法语剧本的人在专业语境里同样说 act out 和 logline。
- **没有对应词的，保留原词，附一句释义。** 戏眼、扣子、ト書き、決定稿 不硬译成英文，输出成 `戏眼 (xìyǎn — the one-line core attraction of an episode)` 这样的形式。
- **剧本正文保持作品本身的语言。** 用英语讨论一个中文剧本很平常：谈话换语言，稿子不换。

这样做牺牲的是**可查验**：除非你读中文，否则看不到指令文件本身，只能看到 agent 的转述。这个代价是实在的，也是那个被撤掉的英文版唯一换来的好处，只是抵不过五种语言长期各维护一份的负担。

**README 另当别论**，它是翻译了的：篇幅短、变动少，而且是新人第一眼看到的东西。日语、韩语、法语三份 README 有意只写到安装、结构和这条规矩为止；完整的 skill 对照表与来源书目留在本文和英文 README 里，不复制四遍，理由和上面一样。

## 四层结构

写长片用第 1、3、4 层；写剧集或舞台作品再加第 2 层。媒介层做的是替换：用该媒介自己的单位取代「为一部电影设计的结构」。

```
1. 通用剧作层   前提 · 结构 · 人物 · 对白 · 场景 · 格式 · 项目调度
2. 媒介层       剧集 · 单集与季结构 · 引擎与 bible · 编剧室 · 半小时喜剧
                舞台 · 戏曲：板腔体与曲牌体两套方法，各带一个全本语料库
3. 传统与行业层 美国 · 日本 · 韩法 · 中国大陆 · 行业生意
4. 大师语料层   契诃夫 · 小津 · 继承之战 · 剧集案例库
```

## 舞台门类

电影和剧集已经覆盖。舞台覆盖了一部分，其余在计划里，并且有一条规则决定什么该开 skill、什么不该。

**规则。** 一个门类会不会让模型写出结构、格式、语言规则都不同的东西？会，就单开 skill；只是题材或风格不同，就放进现有 skill 当案例。题材（谍战、古装、家庭）和导演风格不算；除非像小津那样有完整剧本集，否则当案例收，不单开方法。

**戏曲是两套写法。** 对编剧有意义的分轴是声腔体系，剧种在其次。**曲牌体**（元杂剧、明清传奇、昆曲）是填词：每支曲牌有固定字数、句式、平仄，词填进去；杂剧四折一楔子、一人主唱，传奇按出。**板腔体**（京剧、豫剧、越剧、秦腔、评剧、沪剧）是上下句：七字或十字的上下句为基础，靠板式变化撑起唱段，行当分唱，单位是场。结构单位和唱词写法都不同，所以是两个 skill。同一体系内的剧种，差别只在查哪张韵表（京剧十三辙 vs 豫剧中州韵）、哪张板式表，同一方法配不同的表，放 reference 附录就够了；中国三百多个剧种，一剧种一 skill 就是我们在语言那件事上否掉的同一种组合爆炸。两个不干净的边：**粤剧**梆黄是板腔、小曲是填词，而且用粤语，九声与韵部和普通话完全不同，要不要单开看模型的粤语音韵够不够用来查表，材料进来再测；**川剧**五腔并用，高腔属曲牌体，会同时出现在两个 skill 的附录里。

**现在有什么。** 四个 skill，炼自 25 份材料（十二本方法与理论书、十三种全本、曲谱与文集）：两套声腔体系各一个方法 skill、各一个全本语料库。两个方法 skill 开头都有一张带出处的媒介边界表，说明通用 skill 哪几层能用在戏曲上、哪几层不能，并共用一份美学与排演层的文件。古籍一律取公版本并与原文核对；扫描件无法核对的部分（吴梅、白蛇传的若干处）笔记里明写，skill 不在其上立规则。

**计划补什么，按顺序。** 先补戏曲层自己的两个缺口：豫剧的韵辙分部表（来源只给了原则没给表）和粤剧这条边（粤语音韵可能需要单独处理）。然后是中国话剧一脉在契诃夫之外的东西：曹禺的封闭空间高压结构、老舍《茶馆》的人像展览式无主线结构。音乐剧排最后，歌承担叙事是一套真正不同的规则，现有来源里没有。

**不做什么。** 竖屏短剧与 AI 漫剧，它们的逻辑在投放，没有剧作学可提。按题材拆、按导演拆、按剧种拆的 skill。

**新媒介怎么加进来而不污染通用层。** 一个新 skill；skill 里一张媒介边界表声明哪几层能搬走；`sw-workflow` 入口路径加一行。通用 skill 不改。剧集层（13 → 20）就是这么加的，`sw-story-structure` 一字未动；戏曲这一格也是这么加的，`sw-dialogue` 反而变短了。

## 约定

- frontmatter：`name` 与文件夹同名（kebab-case）；`description` 英文长句以 "Use when …" 收尾，括号内附中文关键词。
- 正文中文；编号原则、表格、清单；skill 之间用文件夹名互相引用。输出语言跟着提问者走，见[多语言支持](#多语言支持)。
- 刻意与具体 agent 解耦：skill 文件里不出现任何 agent 名称、不使用任何 agent 专有语法，因此同一份 `SKILL.md` 在 Claude Code、Codex 或其他遵循 agentskills.io 格式的工具里都能用。每个插件同时带 `.claude-plugin/plugin.json` 与 `.codex-plugin/plugin.json`，共用同一个 `skills/` 目录。
- 来源之间有分歧时并列保留，并注明什么情况用哪个，例如道格拉斯的四幕格子对奥贝格的"幕断只是香肠的尺寸"，主题预设派对主题涌现派。
- 行业事实一律带来源年份（费率、平台格局、幕数变得很快）；国产剧政策数据标注 2014/2016。
- `reference.md` 承载范例与引文，使 `SKILL.md` 保持在约 40 KB 以内。
- 仅供个人学习使用；引文版权归原作者与译者。
